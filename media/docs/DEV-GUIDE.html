The one fact that shapes everything The API and the database live in Node on your PC — the browser is only the UI. Inside an Android APK there is no Node.js and no Express, so every /api call would fail. This is resolved in §06 — read it before shipping.

Running in the Browser
From clone to working app in three commands
# first time only
$ cd /d/DEV/School_system
$ npm install            # express + better-sqlite3
$ npm run setup          # create data/school.db + seed the 24 classes

# every day
$ npm start              # → http://localhost:6000
$ npm run seed:demo      # optional: Arabic demo data for testing

Then open http://localhost:6000. The database, the server and the UI are all local — nothing leaves the machine.

1Port 6000 is “restricted” in Chrome / Edge

It is the X11 port, so browsers block it with ERR_UNSAFE_PORT. Fix: run on another port — PORT=6060 npm start — or launch Chrome with --explicitly-allowed-ports=6000.

2Open it from your phone on the same Wi-Fi

Find the PC’s IPv4 with ipconfig (e.g. 192.168.1.20), then browse http://192.168.1.20:6000. If blocked, allow the port once as admin: netsh advfirewall firewall add rule name="Node 6000" dir=in action=allow protocol=TCP localport=6000

3No hot reload on the server

Restart npm start after editing server/. Client files under client/ need only a browser refresh.

4data/school.db is the whole system

Every student, payment and attendance record lives in this single file — back it up regularly and never commit it.

One-time toolchain — do this before touching Capacitor a) Install a JDK. Easiest: install Android Studio (it bundles its own JDK) — developer.android.com/studio. Or standalone Eclipse Temurin JDK 21 from adoptium.net.
b) Set environment variables (Windows → Environment Variables, or in Git Bash ~/.bashrc): 
$ export ANDROID_HOME="C:\\Users\\Ahmed\\AppData\\Local\\Android\\Sdk"
$ export JAVA_HOME="C:\\Program Files\\Eclipse Adoptium\\jdk-21"   # adjust to your install
$ export PATH="$PATH:$ANDROID_HOME/platform-tools"                # gives you `adb`

# verify — both must answer before anything else works
$ java -version      # should print 21.x
$ adb version        # should print the SDK version
✓Your SDK is already complete

Platforms and build-tools are installed — after setting the two variables there is nothing left to download from SDK Manager.

✓First Gradle build needs internet

Gradle downloads itself + dependencies once; after that, builds work fully offline — like the app itself.

Wrapping the App for Android
Install · build the web assets · generate · compile

1 — Install Capacitor. The config file already knows the app: appId: com.school.nidham, name مدرسة حسين أبوهامد الأهلية, webDir: client/dist, androidScheme: https.

$ cd /d/DEV/School_system
$ npm install @capacitor/core @capacitor/cli @capacitor/android
$ npm install @capacitor/splash-screen @capacitor/haptics @capacitor/filesystem @capacitor/share  # optional plugins

2 — Copy the web assets into client/dist. There is no bundler, so “build” means copy. Save as scripts/build-web.js and add "build:web": "node scripts/build-web.js" to package.json scripts:

// scripts/build-web.js — copy client/ into client/dist/ for Capacitor
const fs = require('fs'), path = require('path');
const src = path.join(__dirname, '..', 'client');
const out = path.join(src, 'dist');
fs.rmSync(out, { recursive: true, force: true });
fs.mkdirSync(out, { recursive: true });
for (const e of ['index.html', 'js', 'screens', 'components', 'styles', 'assets'])
  fs.cpSync(path.join(src, e), path.join(out, e), { recursive: true });
console.log('web assets copied to client/dist');

3 — Generate the Android project, 4 — compile the APK.

$ npm run build:web          # client/ → client/dist/  (run after every client change)
$ npx cap add android        # generates android/  (first time only)
$ npx cap sync android       # copies dist + plugins into the project
$ npx cap open android       # Android Studio → Build APK(s)
# …or command line only:
$ cd android && ./gradlew assembleDebug
# APK appears at android/app/build/outputs/apk/debug/app-debug.apk
$ adb install -r app/build/outputs/apk/debug/app-debug.apk
The habit that saves an hour Capacitor copies files, it does not link them. After any client change: npm run build:web → npx cap sync android → rebuild. Forgetting sync is the #1 “why isn’t my change in the app” cause.

The /api Problem — Read Before Shipping
Why the APK cannot talk to your database as-is
What breaks Inside the APK the WebView loads client/dist from https://localhost — there is no Node.js, no Express and no better-sqlite3 in the APK. Every fetch('/api/…') in client/js/api.js fails. Pick one of two paths:

OPTION A SETUP — capacitor.config.ts

server: {
  androidScheme: 'https',
  url: 'http://192.168.1.20:6000',   // your PC's LAN IP — phone & PC on same Wi-Fi
  cleartext: true,                    // required because http:// (not https)
},

Then npm run build:web → npx cap sync android → rebuild. Remove url + cleartext before the final build — or the APK will always point at that one PC.

Device Testing & Release
Faster loops while developing, then signing for production

FASTER DEVICE TESTING

1Wireless ADB — no cable

Android 11+: Developer options → Wireless debugging → Pair device, then adb pair <ip:port> and adb connect <ip:port>.

2Live reload via Option A

With server.url set, editing client files and refreshing the app shows changes immediately — the APK is just a browser aimed at your dev server.

3See inside the WebView

Logs: adb logcat | grep -i cap. DOM + console: open chrome://inspect in desktop Chrome and pick the device.

4Splash screen is configured

launchShowDuration: 1200 is already in the config — but it is silently ignored unless @capacitor/splash-screen is installed.

RELEASE BUILD — SIGNED APK

# one-time: create a keystore — keep it + its passwords safe, losing them means no more updates
$ keytool -genkey -v -keystore school-release.keystore -alias school -keyalg RSA -keysize 2048 -validity 10000

# wire it into android/app/build.gradle (signingConfigs + release buildType), then:
$ ./gradlew assembleRelease
# android/app/build/outputs/apk/release/app-release.apk
Version bumps live in Gradle, not package.json Change versionCode / versionName in android/app/build.gradle — the npm version does not propagate to the APK.

Tips Cheat-Sheet
The ten things worth remembering
1Port 6000 → ERR_UNSAFE_PORT

Chrome/Edge block it. Use PORT=6060 npm start or the Chrome flag --explicitly-allowed-ports=6000.

2Back up data/school.db

It is the entire system — students, money, attendance. Never commit it to git.

3Copies, not links

Capacitor snapshots files at sync time. Client change → npm run build:web → cap sync → rebuild.

4RTL safe areas

viewport-fit=cover is already set; if content hides behind notches, add env(safe-area-inset-*) padding in main.css.

5Fonts are bundled

Cairo woff2 ships inside client/assets — Arabic renders with zero internet. Keep bundling any new font.

6better-sqlite3 never runs in the WebView

It is a native Node module — on mobile it is replaced by @capacitor-community/sqlite (§06, Option B).

7tel: links work as-is

Phone taps already use tel: and maps open natively — add @capacitor/haptics for attendance tap feedback.

8Exports on device

CSV/Excel exports need @capacitor/filesystem (save to device) + @capacitor/share (send to WhatsApp etc.).

9Chromaflow is your reference

It already has a working android/ build in this workspace — peek at its launch.md for a second Capacitor example.

10Restart, don’t assume

Server edits need npm start again; client edits need sync + rebuild on mobile, only a refresh in the browser.
